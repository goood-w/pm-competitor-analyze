# 材料与证据规则

竞品分析的质量主要取决于材料质量、对比口径和证据边界。本文件用于开始分析前的材料盘点和证据判断。

## 输入材料包

优先让用户提供或确认：

| 材料 | 用途 | 注意事项 |
|---|---|---|
| 我方 PRD / 当前方案 | 作为对比锚点 | 区分已上线、规划中、假设中 |
| 竞品用户手册 / 帮助中心 | 识别实际交付能力、规则、配置项和边界 | 手册未写不等于一定没有，只能标记为未发现 |
| 产品实操记录 / 截图 / 录屏 | 验证入口、流程、状态、异常和反馈 | 记录账号、地区、端、版本和观察日期 |
| 更新日志 / 发布记录 | 判断迭代节奏、资源投入和近期重点 | 过滤营销话术；注意发布日期 |
| 价格页 / 套餐规则 | 判断商业模式、能力边界和付费转化 | 动态信息必须标注时间 |
| 财报 / 客户案例 / 官方白皮书 | 辅助判断战略和客群 | 不直接证明具体功能体验 |
| 行业报告 / 新闻 / 社媒 / 招聘 | 补充市场线索 | 可信度较低，不能单独支撑核心产品结论 |

## 证据可信度

| 等级 | 类型 | 可证明 | 不能证明 |
|---|---|---|---|
| A | 实际产品体验、官方帮助、用户手册、价格页、规则说明 | 当时、该账号条件下的产品表现或官方规则 | 全部用户体验、长期业务效果 |
| B | 官方更新日志、发布会、财报、客户案例 | 官方宣称的更新、战略方向、经营线索 | 功能深度、真实使用效果 |
| C | 可信第三方报告、公开数据平台、应用商店数据 | 市场趋势、规模、排名、用户反馈线索 | 精准经营数据或因果关系 |
| D | 新闻、公众号、社媒、招聘、用户评论 | 线索、反例、舆情和待验证假设 | 核心事实结论 |
| E | 分析者推断 | 解释可能原因 | 已确认事实 |

输出时不要把 B-E 级内容写成 A 级事实。

## 统一任务脚本

多对象对比必须使用同一任务脚本。

| 脚本项 | 填写方式 |
|---|---|
| 用户身份 | 例如中小企业 HR、连锁门店店长、求职者、老师、管理员 |
| 前置条件 | 账号类型、数据量、权限、套餐、端、地区 |
| 目标任务 | 一个具体任务，例如完成一次智能排班、优化一份简历、创建一个课程评估 |
| 观察路径 | 发现入口、理解规则、完成核心动作、异常处理、结果反馈 |
| 成功标准 | 用户如何知道任务完成、系统如何反馈、是否可追踪后续效果 |

如果材料不足以复现实操，用“机制问题清单”替代：

| 机制问题 | 观察点 |
|---|---|
| 谁会进入这个功能？ | 入口、触发条件、权限和付费门槛 |
| 用户要完成什么？ | 核心任务、输入、输出和完成标准 |
| 规则如何工作？ | 配置项、默认值、限制、异常和兜底 |
| 为什么这样设计？ | 用户、商业、运营、数据和组织前提 |
| 我方能否借鉴？ | 适用前提、迁移成本、风险和验证方式 |

## 分析维度库

只选择能回答本次问题的维度。

- 定位与目标用户
- 触发场景与核心任务
- 入口、主流程和完成成本
- 功能、规则、状态、权限和异常
- 信息架构、文案、反馈和交互成本
- 页面目的、视觉层级、心理机制和转化指标
- 定价、套餐、商业模式和服务边界
- 运营、客户成功、数据、生态和组织能力
- 迭代节奏、资源投入和战略方向
- 市场规模、竞争格局和替代方案

## 差异解释

每个重要差异都要尽量解释“为什么会不同”：

- 目标用户和客户规模不同
- 使用频率、任务复杂度或风险等级不同
- 收费模式、获客方式或增长阶段不同
- 数据基础、算法能力或系统集成能力不同
- 运营服务、客户成功或线下交付能力不同
- 地区规则、合规要求或行业惯例不同
- 历史包袱、生态绑定或组织能力不同

## 建议分类

| 类型 | 用法 |
|---|---|
| `adopt` | 可以直接借鉴的原则或表达方式，迁移成本低、证据较强 |
| `adapt` | 值得借鉴但需要结合我方用户、数据、权限、商业模式调整 |
| `avoid` | 不适用于我方，或风险、成本、前提不成立 |
| `test` | 证据不足，但值得用访谈、原型、灰度、数据实验低成本验证 |

每条建议至少包含：要解决的问题、适用前提、预期收益、风险、验证方式。

## 停止条件

满足以下条件即可停止采集并进入报告：

- 决策问题已有直接证据，或关键缺口已明确标注为无法验证。
- 主要差异能回溯到来源、日期、版本或体验条件。
- 新增材料只重复既有信息，不再改变结论。
- 剩余未知项不会影响当前建议，或已经进入 `test` 类验证建议。

不要为了填满模板继续无边界搜索。
