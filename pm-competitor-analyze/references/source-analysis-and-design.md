# 链接分析与 Skill 设计沉淀

本文件说明本 Skill 的设计依据。四个参考链接分别贡献了不同层次的方法：专项竞品调研、完整竞品分析文档、页面/流程拆解、完整市场/战略框架。使用时注意：这些资料是方法来源，不是具体竞品事实来源。

## 1. 《如何用 Skill 做竞品调研？》

来源：https://www.woshipm.com/pd/6395378.html

### 竞品分析流程

该文是本 Skill 的主干来源。它强调 AI 不适合直接无边界上网调研，因为公开新闻、营销稿和发布会资料容易形成浅层拼接；更有效的做法是由产品经理准备高质量材料，再让 AI 消化、对比和推断。

可沉淀流程：

1. 明确我方产品问题或 PRD 模块。
2. 选择一个具体模块或专项能力，不做全产品泛分析。
3. 收集竞品用户手册、更新日志、必要财报或官方资料。
4. 让 AI 对比我方 PRD 与竞品材料，识别能力差距和实现差异。
5. 结合更新节奏和资源投入，推断竞品战略意图。
6. 回到自身产品规划，形成可执行启示。

### 竞品分析文档结构

该文给出的固定输出结构可抽象为：

1. 竞品演进路线图
2. 重点功能与产研资源投入分布
3. 背后企业战略洞察
4. 对自身产品规划的启示
5. 核心功能说明
6. 差异化对比

### 生成逻辑

生成逻辑不是“列功能”，而是“以我方 PRD 为锚点做专项差异分析”：

- 先看我方正在做什么或准备做什么。
- 再看竞品官方材料中已经交付了什么。
- 然后判断差异属于能力缺口、规则差异、交互差异、商业边界差异还是战略选择差异。
- 最后输出对我方有用的 `adopt / adapt / avoid / test` 建议。

### 所需技能

- 用户手册阅读与功能边界识别
- 更新日志分析与路线图推断
- PRD 对照和专项能力拆解
- 产研资源投入判断
- 竞品战略意图推断
- 将差异转化为产品规划建议

### 对本 Skill 的吸收

- 默认模式设为 `专项能力对比`。
- 要求优先使用 PRD、用户手册、官方帮助、更新日志。
- 要求分析粒度聚焦到模块、流程或专项能力。
- 把“固定输出结构”转为可复用 Markdown 模板。
- 强制区分事实、推断和建议，避免凭竞品存在就直接生成需求。

## 2. 《原来优秀的产品经理都是这么写竞品分析文档的》

来源：https://www.woshipm.com/share/5961700.html

### 竞品分析流程

该文提供的是传统完整竞品分析流程，适合正式汇报、市场研究和商业决策：

1. 明确竞品分析目的。
2. 确定研究对象和方法。
3. 收集市场、竞品、用户、价格、技术等信息。
4. 对功能、体验、营销、价格等维度展开分析。
5. 识别机会、挑战、优劣势。
6. 形成结论和行动计划。

### 竞品分析文档结构

可沉淀结构：

1. 引言：目的、对象、方法
2. 市场概述：市场规模、增长趋势、主要参与者
3. 竞品描述：产品、服务、定位、策略
4. 分析目的：趋势、机会、自身改进
5. 分析内容：功能、用户体验、营销、技术、价格
6. 消费者或用户分析
7. 优劣势分析，可使用 SWOT / PEST
8. 市场机会与挑战
9. 结论和行动计划

### 生成逻辑

该文的逻辑是“从环境到对象，再到对比，再到策略”：

- 先把市场和竞争环境说清。
- 再把主要竞品定位和策略说清。
- 然后按多个维度比较。
- 最后输出机会、挑战和行动计划。

### 所需技能

- 市场规模和趋势分析
- 竞品定位归纳
- 用户和消费者分析
- 功能体验分析
- 价格、营销和技术维度分析
- SWOT / PEST 等框架使用
- 行动计划表达

### 对本 Skill 的吸收

- 保留“背景与范围 -> 对象选择 -> 维度对比 -> 结论建议 -> 行动计划”的文档骨架。
- 不把所有维度作为默认必填项，只作为可选维度库。
- 在用户明确要市场进入、融资叙事或战略扫描时，启用 `市场/战略扫描` 模式。

## 3. 《AI 做竞品分析实战：输出深度洞察，效率飙升 80%》

来源：https://www.woshipm.com/ai/6225056.html

### 竞品分析流程

该文贡献的是轻量页面/流程拆解方法：

1. 截取竞品关键页面或流程。
2. 明确分析目标和用户背景。
3. 通过清晰提示词让 AI 分析页面目的、用户旅程和元素意图。
4. 根据输出继续追问和迭代。
5. 抽取可执行学习点。

### 竞品分析文档结构

可沉淀结构：

1. 页面设计目的
2. 用户主要任务和核心业务指标
3. 3-7 步用户旅程
4. UI 元素与功能意图
5. 文案、视觉层级、社会认同、紧迫感等心理机制
6. SWOT 或风险拆解
7. 可执行学习点，按影响力和可行性排序

### 生成逻辑

该文的逻辑是“从页面表象反推业务目的”：

- 页面不是只看视觉好坏，而是看它服务什么任务。
- UI 元素不是孤立组件，而是入口、信任、转化、教育或降低阻力的手段。
- 输出不止是拆解，还要落到我方可以测试或借鉴的动作。

### 所需技能

- 截图/OCR 阅读
- 页面信息架构分析
- 用户旅程复原
- UI 元素意图推断
- 转化指标意识
- 设计心理机制识别
- 可借鉴点和模仿风险判断

### 对本 Skill 的吸收

- 增加 `页面/流程拆解` 模式。
- 在模板中加入页面目的、用户旅程、UI 元素意图、心理机制、可执行学习点。
- 增加证据边界：页面截图只能证明当时页面表现，不能证明完整产品规则或真实业务结果。

## 4. GitHub: yuanzheng10/competitive-analysis

来源：https://github.com/yuanzheng10/competitive-analysis/tree/main

### 竞品分析流程

该仓库提供的是完整竞品分析 Skill 框架：

1. 收集自身品牌或产品信息。
2. 定义竞品分析范围。
3. 按分析深度和关注领域收集信息。
4. 验证数据来源、采集时间、估算值和官方数据。
5. 进行深度分析。
6. 生成报告。

### 竞品分析文档结构

可沉淀为 10 大维度：

1. 市场现状与行业分析
2. 竞品背景分析
3. 产品定位与企业愿景
4. 目标用户分析
5. 竞品数据分析
6. 产品与功能分析
7. 运营推广策略
8. 盈利模式分析
9. SWOT 分析
10. 结论与建议

### 生成逻辑

该仓库的逻辑是“完整研究工具包”：

- 先建立市场、公司和产品层背景。
- 再分析用户、数据、功能、交互、运营、商业模式。
- 最后综合 SWOT 和建议。
- 输出可以是 Markdown、Word、Excel、PPT 等多种格式。

### 所需技能

- 市场研究
- 商业模式分析
- 数据源可信度判断
- 功能和交互拆解
- 运营推广分析
- 盈利模式分析
- SWOT 分析
- 多格式报告组织

### 对本 Skill 的吸收

- 将 10 大维度沉淀为“分析维度库”，不默认全部展开。
- 将完整框架用于 `市场/战略扫描` 模式。
- 把数据来源、采集时间、官方数据和估算值区分写入证据规则。

## 5. 最终 Skill 设计思路

本 Skill 采用“四源融合、轻量优先”的设计：

| 来源 | 在本 Skill 中的角色 |
|---|---|
| 《如何用 Skill 做竞品调研？》 | 主流程：以我方 PRD/问题为锚点，做专项能力分析 |
| 《优秀产品经理竞品分析文档》 | 文档骨架：背景、对象、维度、结论、行动计划 |
| 《AI 做竞品分析实战》 | 页面模式：截图/页面/流程拆解，连接 UI 与业务指标 |
| GitHub competitive-analysis | 深度框架：10 大维度和市场/战略扫描模式 |

默认优先级：

1. 用户有明确模块、PRD 或页面：用 `专项能力对比` 或 `页面/流程拆解`。
2. 用户只想学习一个标杆机制：用 `单品机制拆解`。
3. 用户明确要市场进入、融资、战略或商业模式：用 `市场/战略扫描`。

## 6. 生成逻辑总览

1. 把用户请求改写成可回答的产品决策问题。
2. 判断分析模式和深度。
3. 盘点材料，按可信度区分事实、官方说法、用户评价、推断和假设。
4. 设计统一任务脚本或机制问题清单。
5. 按相关维度分析，不为填模板展开无关内容。
6. 解释差异原因，而不是停在功能有无。
7. 输出 `adopt / adapt / avoid / test` 建议。
8. 明确证据局限和后续补证据方式。

## 7. Skill 需要强化的能力

- 问题收敛：从“帮我分析竞品”变成“本次要支持哪个产品决策”。
- 材料判断：知道用户手册、更新日志、截图、报告分别能证明什么。
- 同口径对比：使用统一用户身份、前置条件、任务脚本和观察维度。
- 机制解释：识别入口、流程、规则、状态、权限、异常、反馈和商业边界。
- 页面推断：把 UI 元素、文案和视觉层级与转化、信任、教育、降低阻力联系起来。
- 商业推断：从价格、套餐、客户案例、渠道和服务边界解释产品选择。
- 证据边界：明确哪些是事实，哪些只是推断或待验证假设。
- 建议收敛：把外部做法转成我方可采用、需改造、应避免或需测试的动作。
